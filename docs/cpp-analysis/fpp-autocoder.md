# FPP autocoder-generated code contract (component base classes, ports, types) — the API surface a Rust port must replace with macros/codegen

> Analysis of the C++ F Prime implementation (github.com/nasa/fprime) produced to guide this Rust port.
> Source tree analyzed: local clone at commit of 2026-08. File paths refer to that C++ tree.

## Overview

F Prime components are written as C++ classes deriving from FPP-autocoded base classes (files `*Ac.hpp/cpp`, generated by fpp-to-cpp 3.3.0 per requirements.txt; not checked in — contract inferred from Fw/ base classes, FppTestProject/FppTest, and docs/user-manual/framework/autocoded-functions.md). The generated `<Comp>ComponentBase` derives from Fw::PassiveComponentBase, Fw::QueuedComponentBase, or Fw::ActiveComponentBase (Fw/Comp/) per component kind. It owns typed input/output port objects (deriving Fw::InputPortBase/OutputPortBase), declares pure-virtual `<port>_handler` methods for input ports and commands, and provides concrete methods for output-port invocation, event logging, telemetry writes, parameter access, time lookup, and command registration/response. Async inputs (ports, commands, internal interfaces, state-machine signals) are serialized into a fixed-layout message and pushed onto the component's Os::Queue; the generated `doDispatch()` deserializes and re-invokes handlers on the component thread. All user-visible data types (enums, arrays, structs, strings) are generated as Fw::Serializable classes with a deterministic big-endian wire format used identically for port messages, command args, events, telemetry, parameters, and ground dictionaries. Everything is statically sized: no heap, buffers are `Fw::LinearBufferTemplate<N>` (Fw/Types/LinearBufferTemplate.hpp), sizes come from config constants (default/config/FpConstants.fpp, AcConstants.fpp) and per-type SERIALIZED_SIZE constants. The Rust port must reproduce: the exact wire formats, the handler/invoke naming contract (as idiomatic traits/methods), the queue-message dispatch loop with per-port overflow policy, and the command/event/tlm/param glue including id-base offsetting.

### Generated typed-component base: ports

Files: `docs/user-manual/framework/autocoded-functions.md`, `FppTestProject/FppTest/component/common/typed.hpp`, `FppTestProject/FppTest/component/tests/TesterHelpers.cpp`, `Fw/Port/InputPortBase.hpp`

For each input port `p: [n] PortType`: pure virtual `void|Ret p_handler(FwIndexType portNum, args...) = 0` implemented by user (value args passed by value for primitives, const& for classes/strings, non-const & for `ref` args; FPP `string` args surface as const Fw::StringBase& / Fw::StringBase&); public `Fw::InputPortType* get_p_InputPort(FwIndexType)` for topology wiring. sync input: caller thread invokes handler directly; guarded input: handler wrapped in a single per-component mutex shared by ALL guarded ports/commands; async input: args serialized to queue message (see wire format), virtual `p_preMsgHook(portNum,args)` (default empty) called before enqueue; overflow policy per-port from FPP qualifiers `assert` (default; FW_ASSERT on queue-full), `drop` (increment dropped count, silently discard), `block` (blocking send), `hook` (calls generated virtual `p_overflowHook(portNum,args)` — FppTest OverflowTests). ### Async queue message wire contract + dispatch

Files: `Fw/Comp/ActiveComponentBase.cpp`, `FppTestProject/FppTest/component/tests/OverflowTests.cpp`, `Os/Queue.hpp`

Queue message = serialization into an internal buffer sized to the largest async invocation: [FwEnumStoreType msgType (I32 BE)] [FwIndexType portNum (I16 BE)] [args serialized in order]. msgType enum is generated per component: value 0 is reserved for ACTIVE_COMPONENT_EXIT (Fw::ActiveComponentBase enum, serialized alone by exit()); other members enumerate each async input port, async command, internal interface, and SM-instance signal. For async commands the args portion is [opCode][cmdSeq][CmdArgBuffer as length-prefixed buffer]. doDispatch(): queue.receive (BLOCKING for active components, NONBLOCKING for queued/cooperative), deserialize msgType, on EXIT return MSG_DISPATCH_EXIT, else deserialize portNum + args and call the corresponding handler/handlerBase; deserialize failures assert. createQueue(depth,msgSize) called from generated init(queueDepth, instance). Message priority comes from FPP `priority N` on the port/command/internal-port; Os::Queue is a priority queue (max-heap, FwQueuePriorityType=U8).

## Wire formats

### Primitive serialization (all FPP types, everywhere)

Big-endian by default (Endianness::BIG; explicit byte-shift loops in Fw/Types/Serializable.cpp lines 88-210), optional LITTLE mode reverses byte order. U8/I8: 1 byte. U16/I16: 2, U32/I32: 4, U64/I64: 8, MSB first. F32/F64: IEEE-754 bits memcpy'd to U32/U64 then same byte order. bool: 1 byte, true=0xFF (FW_SERIALIZE_TRUE_VALUE), false=0x00; deserialize rejects any other value with FW_DESERIALIZE_FORMAT_ERROR. Pointers: serialized as PlatformPointerCastType (uintptr-width uint, 8 bytes on 64-bit unix). Plain C++ enums serialize via FwEnumStoreType=I32; FPP enums serialize as their representation type (default I32).

### String

[FwSizeStoreType length (U16 BE)] [length raw bytes, no NUL]. Fw/Types/ConstStringBase.cpp serializeTo; deserialize fails if length > destination maxLength or > remaining bytes. Max wire size for `string size N` = 2+N; default `string` = 2+256=258 (FppTest/sizeof asserts).

### Length-prefixed byte buffer / LinearBufferBase

INCLUDE_LENGTH mode (default for serializeFrom(U8*,len)): [FwSizeStoreType length (U16 BE)][bytes]; OMIT_LENGTH: raw bytes only. serializeFrom(LinearBufferBase&): [FwSizeStoreType size][contents] — this is how CmdArgBuffer/LogBuffer etc. nest inside other messages (Fw/Types/Serializable.cpp lines 238-303).

### Fw::Time / TimeValue

11 bytes: [timeBase: FwTimeBaseStoreType U16 BE][timeContext: U8][seconds: U32 BE][useconds: U32 BE] (Fw/Time/Time.fpp struct TimeValue; Time.hpp SERIALIZED_SIZE = 2+1+4+4; Time::serializeTo delegates to the generated TimeValue struct).

### FPP enum / array / struct

Enum: rep-type-width integer BE (U16-rep enum = 2 bytes; default rep I32 = 4 bytes). Array [n] T: n elements serialized consecutively, no count, no padding (TestArray1=[3]I64 → 24 bytes). Struct: members serialized in FPP declaration order, no header/padding; string members use the string format at their declared size (NonPrimitiveTest.cpp lines 97-100 asserts the exact sum).

### Component queue message (generated doDispatch contract)

[msgType: FwEnumStoreType I32 BE][portNum: FwIndexType I16 BE][port args in declaration order]. Exit message is just [I32 = ACTIVE_COMPONENT_EXIT (0)] (ActiveComponentBase::exit(), Fw/Comp/ActiveComponentBase.cpp lines 49-54 — buffer sized sizeof(I32), proving msgType is first token). Async command message args = [opCode: U32][cmdSeq: U32][CmdArgBuffer: U16 size + bytes].

### Command packet (uplink, FW_PACKET_COMMAND)

[packetDescriptor: FwPacketDescriptorType U16 = 0x0000][opcode: FwOpcodeType U32][arg bytes to end of packet, no length] (Fw/Cmd/CmdPacket.cpp deserialize: descriptor via ComPacket base, opcode, then copyRaw of remainder into CmdArgBuffer; serialize asserts false — FSW never serializes command packets).

### Log (event) packet, FW_PACKET_LOG

[U16 descriptor = 0x0002][id: FwEventIdType U32 BE][Time 11 bytes][event args serialized back-to-back, OMIT_LENGTH — no size token] (Fw/Log/LogPacket.cpp). Telemetry channel packet FW_PACKET_TELEM=0x0001 analogous: [U16=1][id U32][Time 11B][value bytes OMIT_LENGTH]; TlmPacket (packetized) = [numEntries][entries].

### GenericHub serialized-port tunneling

[type: U32 BE (hub message type enum)][port index: U32 BE][size-prefixed data: FwBuffSizeType/FwSizeStoreType + bytes] (Svc/GenericHub/GenericHub.cpp lines 38-42); events/telemetry forwarded as [id][Time][buffer], command responses as [opCode][cmdSeq][response].

## Threading / concurrency

Three component kinds (docs/user-manual/overview/03-port-comp-top.md): passive (no queue/thread — all handlers run on caller thread), queued (queue, no thread — async messages dispatched only when someone calls doDispatch/dispatchAvailableMessages from a synchronous handler or scheduler tick), active (queue + own Os::Task). Sync input ports: direct virtual call on caller thread. Guarded input ports and guarded commands: caller thread, serialized by ONE mutex per component instance shared across all guarded entry points. Async ports/commands/internal-interfaces/SM-signals: serialized into a priority queue (Os::Queue, FwQueuePriorityType U8, per-message priority from FPP); the active component task blocks on receive; queued components use nonblocking receive. Queue-full policy is per-port: assert (default), drop (count via incNumMsgDropped), block, or overflow hook. Active task lifecycle is an explicit 4-state machine (CREATED/DISPATCHING/FINALIZING/DONE) factored so cooperative (non-preemptive) platforms can pump one step at a time; dispatch on a cooperative task returns EMPTY rather than blocking. exit() posts a zero-priority nonblocking EXIT message. Event/tlm/param/time glue executes on whatever thread calls the generated method; the framework assumes output port invocation is safe from any thread (target components decide sync/guarded/async).

## Porting notes

1) Model the generated base class as a macro- or build-script-generated struct implementing traits: split into (a) a serialization crate reproducing LinearBufferBase exactly — statuses as an enum with the 10 listed variants, ser/deser cursors with the quirk that any write resets the read cursor, BE default with per-call endianness, bool as 0xFF/0x00, U16 length prefixes via FwSizeStoreType; property-test against byte vectors captured from C++. 2) Represent FPP types as: enums = Rust enum + rep-type newtype with isValid semantics for non-contiguous values (deserialization must validate); arrays = [T; N] newtype; structs = plain structs with declaration-order derive(Serialize) — a derive macro mirroring fpp field order is the natural mechanism; strings = fixed-capacity string types parameterized by const N with truncate-on-assign and the 2+N wire size. 3) Port handlers: input ports become a trait with one method per port (`fn p_handler(&mut self, port_num: FwIndexType, ...)`); output ports become invoker structs holding Option<connection>; keep the panic-if-unconnected (FW_ASSERT) semantics and isConnected checks. The C++ `ref` out-parameters on ports (aRef etc.) must become &mut args — they are part of the synchronous-call contract and are serialized for async ports too. 4) Reproduce the queue message layout bit-for-bit (I32 msgType, I16 portNum, args) only if wire compatibility of hub/serial ports is required; otherwise keep msgType=0 reserved for EXIT and the per-message priority + overflow policy (assert/drop/block/hook) exactly. 5) Command glue: relative opcodes + idBase offsetting, FORMAT_ERROR on deser failure and on residual bytes, VALIDATION_ERROR for invalid enums, exactly-once cmdResponse_out. 6) Events: per-event throttle counters (count N then suppress until explicit clear) and format-string conversion ({} → display, {x}/{o}/{d}/{c}/{.Nf} etc.) should be computed at codegen time into a static formatter. 7) Keep FwIndexType signed (I16) and FwSizeType u64 — mixing these up breaks wire formats (portNum is serialized as I16). 8) Implement the active-component lifecycle as the explicit 4-state machine to preserve cooperative-scheduler support. 9) State machines: generate synchronous sendSignal transition functions with exit→transition-do→entry action order; component-integrated instances route through the queue with SmSignalBuffer max 128 bytes. 10) Config: expose FpConstants/AcConstants/FpConfig switches as build-time constants (feature flags for FW_ENABLE_TEXT_LOGGING, FW_OBJECT_NAMES, FW_PORT_SERIALIZATION, FW_AMPCS_COMPATIBLE=0).

## Gotchas

- Any serializeFrom() call resets the deserialize cursor to 0 (m_deserLoc=0) — code that interleaves reads and writes on one buffer depends on this.
- bool wire values are strictly 0xFF/0x00; deserializing anything else is FW_DESERIALIZE_FORMAT_ERROR, not truthiness.
- Length prefixes are FwSizeStoreType = U16, not FwSizeType; serializeSize returns FW_SERIALIZE_FORMAT_ERROR (not NO_ROOM) when a size exceeds U16.
- serializeFrom(U8*, len) with no mode argument INCLUDES a length prefix by default; packet code that wants raw bytes must pass OMIT_LENGTH — LogPacket/TlmPacket deliberately omit it so ground software sees no size token.
- Default FPP string size in this repo serializes as 2+256=258 bytes (FppTest/sizeof asserts 258) — do not assume FPP's documented default of 80.
- FwIndexType (port numbers) is SIGNED I16 on unix; FwEnumStoreType (queue msgType, init instance arg) is I32 — both appear in wire layouts.
- Strings passed through event logging are truncated to FW_LOG_STRING_MAX_SIZE=200 at serialization time via the two-arg serializeTo(buffer, maxLength), independent of the string's own capacity.
- Enum isValid() checks exact declared constants, including non-contiguous sets (Interval test: 1,2,6,99,102 invalid; 0,3,4,5,10,100,101 valid) — a range check is wrong.
- TimeBase::TB_DONT_CARE is 0xFFFF because FwTimeBaseStoreType is U16; changing the store type changes the sentinel.
- Queue overflow default is FW_ASSERT (crash), not drop — 'drop'/'block'/'hook' must be opted into per port in FPP; drops increment a per-component counter.
- String deserialize failure leaves the previous content but force-null-terminates at max capacity; success null-terminates at the deserialized length.
- CmdPacket deserialize with an empty remainder must clear the arg buffer (resetSer) or a no-arg command inherits stale bytes — recent bug fix visible in Fw/Cmd/CmdPacket.cpp.
- Guarded ports share ONE mutex per component (not per port); a guarded handler calling another of its own guarded entry points would self-deadlock unless the mutex is reentrant (it is not).
- Command dispatch compares opcode minus idBase; all dictionary ids (opcodes, events, channels, params) are base-relative constants in generated code and offset at runtime via setIdBase.
- ActiveComponentBase::exit() only enqueues the EXIT message (nonblocking, priority 0); the task actually stops later when dispatch drains to it, and finalizer() runs after, on the component thread.
- F32/F64 are byte-swapped like integers (bit-pattern through U32/U64) — a port must not use native-endian float writes.
- sizeof() in FPP means serialized size, not C++ sizeof; FW_CMD_ARG_BUFFER_MAX_SIZE=506 derives from 512 - sizeof(FwOpcodeType=4) - sizeof(FwPacketDescriptorType=2).
