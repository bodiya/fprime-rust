# F Prime object/port/component model (Fw/Obj, Fw/Port, Fw/Comp, Fw/Ports, Fw/Interfaces, Os/Queue)

> Analysis of the C++ F Prime implementation (github.com/nasa/fprime) produced to guide this Rust port.
> Source tree analyzed: local clone at commit of 2026-08. File paths refer to that C++ tree.

## Overview

This subsystem is the runtime skeleton every F Prime deployment hangs off. Fw::ObjBase is the root of the class hierarchy (name storage + optional registry callback on init()). Fw::PortBase/InputPortBase/OutputPortBase are the untyped port bases; FPP-autocoded typed port classes (not in repo; generated by fprime-fpp 3.3.0 into the build cache) derive from them and route an invocation to a static callback registered with the receiving component. Fw::PassiveComponentBase / QueuedComponentBase / ActiveComponentBase are the three component kinds: passive (no queue/thread), queued (Os::Queue, no thread; user code drains via doDispatch/dispatchAvailableMessages from some sync port), active (Os::Queue + Os::Task running a 4-state lifecycle machine: preamble -> blocking dispatch loop -> finalizer). Async port/command/internal-interface invocations are serialized (big-endian) into a message buffer and pushed onto the component's priority queue; doDispatch (pure virtual here, generated per component) pops one message, deserializes, and calls the user's virtual handler. Sync/guarded invocations are plain (mutex-wrapped) virtual calls on the caller's thread. Serialize ports (Input/OutputSerializePort) pass an opaque serialized buffer through untyped connections for hub/C&DH patterns. Topology wiring is done at startup by handing input-port pointers to output ports via generated get_/set_ accessors. Os::Queue is a facade over a placement-new delegate (default: Os/Generic/PriorityQueue, max-heap by priority, FIFO within priority, condition-variable blocking). Everything is configured by FpConfig.h switches (FW_OBJECT_NAMES, FW_PORT_SERIALIZATION, etc.) and FPP type aliases (FwIndexType=I16, FwSizeType=U64, FwEnumStoreType=I32, FwQueuePriorityType=U8 on unix defaults).

## Key items

### Fw::ObjBase / Fw::ObjRegistry

Files: `Fw/Obj/ObjBase.hpp`, `Fw/Obj/ObjBase.cpp`

Root class. Protected ctor takes const char* name; nullptr name becomes "NoName" (only when FW_OBJECT_NAMES==1; otherwise name ignored, no storage). m_objName is Fw::ObjectName (truncating fixed buffer, FW_OBJ_NAME_BUFFER_SIZE=80). init() (protected, non-virtual) calls s_objRegistry->regObject(this) if a registry was set via static setObjRegistry(); registry set is not thread-safe. toString(buf,size) virtual (FW_OBJECT_TO_STRING==1, requires FW_OBJECT_NAMES==1): formats "Obj: %s" with name; on format failure writes empty string; asserts size>0 and buf!=nullptr. ObjRegistry: pure virtual regObject(ObjBase*).

### Fw::SimpleObjRegistry

Files: `Fw/Obj/SimpleObjRegistry.hpp`, `Fw/Obj/SimpleObjRegistry.cpp`

Fixed array ObjBase*[FW_OBJ_SIMPLE_REG_ENTRIES] (default 500, FpConstants.fpp). Ctor registers itself via ObjBase::setObjRegistry(this); dtor sets registry to nullptr. regObject asserts on overflow then appends. dump()/dump(name) log via Fw::Logger using toString into a char[FW_OBJ_SIMPLE_REG_BUFF_SIZE=255]. clear() just zeroes count (stale pointers remain).

### Fw::PortBase

Files: `Fw/Port/PortBase.hpp`, `Fw/Port/PortBase.cpp`

Derives ObjBase with nullptr name (port names are set during topology wiring via setObjName). m_connObj: ObjBase* of connected peer; isConnected() == (m_connObj != nullptr). Tracing (FW_PORT_TRACING==1, default on): static s_trace + per-port override pair (m_ovr_trace,m_trace) set by ovrTrace(ovr,trace); trace() asserts isConnected() and logs "Trace: <name|ptr>". C linkage setConnTrace(bool) sets global trace. toString format "Port: %s %s->(%s)" = (name, "C"/"NC", peer name|"None"); subclasses override getToStringFormatString() only. Copy ctors/assignment disabled.

### Fw::InputPortBase

Files: `Fw/Port/InputPortBase.hpp`, `Fw/Port/InputPortBase.cpp`

Adds m_comp (PassiveComponentBase*, init nullptr) and m_portNum (FwIndexType, init -1). setPortNum asserts portNum>=0. When FW_PORT_SERIALIZATION==1 declares pure virtual SerializeStatus invokeSerial(LinearBufferBase&) — typed generated input ports implement it by deserializing args and calling the registered callback; that lets any OutputSerializePort feed a typed input port.

### Fw::OutputPortBase

Files: `Fw/Port/OutputPortBase.hpp`, `Fw/Port/OutputPortBase.cpp`

When FW_PORT_SERIALIZATION==1 holds m_serPort (InputPortBase*, init nullptr). registerSerialPort(port): asserts non-null, sets both m_connObj and m_serPort — this is how a typed OUTPUT port is connected to an InputSerializePort (generated set_<port>_OutputPort overload calls it). invokeSerial(buffer): asserts m_serPort non-null, forwards to m_serPort->invokeSerial(buffer). Generated typed output ports additionally hold a typed m_port pointer set by addCallPort(typed input*); their invoke() asserts connected, calls trace(), then either the typed input's invoke (direct virtual-call path) or serializes args and calls invokeSerial when only m_serPort is set.

### Fw::InputSerializePort / OutputSerializePort

Files: `Fw/Port/InputSerializePort.hpp`, `Fw/Port/InputSerializePort.cpp`, `Fw/Port/OutputSerializePort.hpp`, `Fw/Port/OutputSerializePort.cpp`

Only compiled when FW_PORT_SERIALIZATION==1. InputSerializePort: final; callback typedef CompFuncPtr = void(*)(PassiveComponentBase* callComp, FwIndexType portNum, LinearBufferBase& arg); addCallComp(comp,func) asserts non-null and stores m_comp/m_func. invokeSerial asserts m_comp and m_func set, calls m_func(m_comp, m_portNum, buffer), always returns FW_SERIALIZE_OK (typed ports return the deserialize status; pass-through has nothing to deserialize). OutputSerializePort: final, no extra state; connection uses inherited registerSerialPort; serialize ports cannot carry return values.

### Fw::PassiveComponentBase

Files: `Fw/Comp/PassiveComponentBase.hpp`, `Fw/Comp/PassiveComponentBase.cpp`

ObjBase subclass. State: m_idBase (FwIdType=U32, init 0; runtime offset added to opcodes/event/tlm/param ids; setIdBase/getIdBase public) and m_instance (FwEnumStoreType=I32, init 0; protected getInstance). protected init(FwEnumStoreType instance) calls ObjBase::init() then stores instance. virtual deinit() {} public. toString format "Comp: %s". Guarded-port mutex is NOT here — it lives in the generated component base.

### Fw::QueuedComponentBase

Files: `Fw/Comp/QueuedComponentBase.hpp`, `Fw/Comp/QueuedComponentBase.cpp`

Adds Os::Queue m_queue (protected) and m_msgsDropped (FwSizeType, init 0; getNumMsgsDropped/incNumMsgDropped — generated code increments on 'drop' queue-full policy). MsgDispatchStatus enum (public): MSG_DISPATCH_OK=0, MSG_DISPATCH_EMPTY=1, MSG_DISPATCH_ERROR=2, MSG_DISPATCH_EXIT=3. pure virtual doDispatch() — generated per component: receives one message from m_queue, deserializes, invokes handler. createQueue(depth,msgSize): queue name = object name when FW_OBJECT_NAMES==1 else "CompQ_<n>"; calls m_queue.create(getInstance(), name, depth, msgSize). dispatchAvailableMessages(): snapshots n=getMessagesAvailable(), calls doDispatch() up to n times, breaks and returns first non-OK status (returns MSG_DISPATCH_OK if n==0 or all OK). deinit() override calls m_queue.teardown(). toString fmt "QueueComp: %s".

### Fw::ActiveComponentBase

Files: `Fw/Comp/ActiveComponentBase.hpp`, `Fw/Comp/ActiveComponentBase.cpp`

Adds Os::Task m_task and private Lifecycle m_stage: CREATED=0, DISPATCHING=1, FINALIZING=2, DONE=3 (ctor: CREATED). public enum { ACTIVE_COMPONENT_EXIT } (=0). start(priority=TASK_PRIORITY_DEFAULT(=U8 max 255), stackSize=TASK_DEFAULT(=U64 max), cpuAffinity, identifier): task name = object name (else "ActComp_<n>"); routine = s_taskStateMachine if m_task.isCooperative() (default false) else s_taskLoop; asserts start status OP_OK. s_taskStateMachine(void*) runs ONE stage per call: CREATED -> preamble(), ->DISPATCHING; DISPATCHING -> if dispatch()==MSG_DISPATCH_EXIT ->FINALIZING; FINALIZING -> finalizer(), ->DONE; DONE -> no-op (cooperative schedulers keep calling it forever; threaded loop exits). s_taskLoop = while(m_stage!=DONE) stateMachine. dispatch(): if cooperative and 0 messages available return MSG_DISPATCH_EMPTY (avoids blocking), else return doDispatch() (generated active doDispatch uses a BLOCKING receive). exit(): serializes I32 ACTIVE_COMPONENT_EXIT into a stack buffer sized sizeof(ACTIVE_COMPONENT_EXIT) and m_queue.send(buf, priority 0, NONBLOCKING), send status DISCARDED — exit can be silently lost on a full queue. join() delegates m_task.join(); deprecated join(void**) ignores the pointer. preamble()/finalizer() virtual empty defaults, run on component's own thread. toString fmt "ActComp: %s".

### Os::Queue facade + generic PriorityQueue

Files: `Os/Queue.hpp`, `Os/Queue.cpp`, `Os/Generic/PriorityQueue.cpp`, `Os/Generic/Types/MaxHeap.cpp`

QueueInterface::Status: OP_OK=0, ALREADY_CREATED=1, EMPTY=2, UNINITIALIZED=3, SIZE_MISMATCH=4, SEND_ERROR=5, RECEIVE_ERROR=6, INVALID_PRIORITY=7, FULL=8, NOT_SUPPORTED=9, ALLOCATION_FAILED=10, UNKNOWN_ERROR=11. BlockingType: BLOCKING=0, NONBLOCKING=1. Os::Queue is final; ctor placement-news implementation via QueueInterface::getDelegate into alignas(FW_HANDLE_ALIGNMENT=8) U8[FW_QUEUE_HANDLE_MAX_SIZE=368]. create(id,name,depth,msgSize): asserts depth>0 && msgSize>0; returns ALREADY_CREATED if m_depth||m_size already nonzero; on OP_OK stores name/depth/size, increments global s_queueCount under static mutex, and calls s_queueRegistry->registerQueue(this) when FW_QUEUE_REGISTRATION==1 and registry set. send(buf,size,prio,block): asserts buf non-null; UNINITIALIZED if not created; SIZE_MISMATCH if size > messageSize; else delegate. receive(dest,cap,...): SIZE_MISMATCH if cap < messageSize (full capacity required regardless of actual message length). LinearBufferBase overloads: send uses getBuffAddr()/getSize(); receive resetSer()s destination, receives into getBuffAddrSer() with getCapacity(), then setBuffLen(actualSize) (failure -> SIZE_MISMATCH). Generic PriorityQueue delegate: mutex + two condition vars; NONBLOCKING send on full -> FULL; NONBLOCKING receive on empty -> EMPTY; BLOCKING waits on condvar loop; MaxHeap orders by priority DESC, FIFO among equal priority (higher FwQueuePriorityType value dequeued first). QueueRegistry: virtual registerQueue(Queue*).

Invocation chain: user calls <port>_out(portNum,args) -> asserts portNum < getNum_<port>_OutputPorts() -> outputPort[portNum].invoke(args) -> asserts connected, trace(), then typed inputPort->invoke(args) -> m_func(m_comp, m_portNum, args) -> static thunk casts m_comp to generated base and calls: sync kind: <port>_handlerBase -> virtual <port>_handler (pure virtual in generated base, implemented by user); guarded kind: same but wraps in the component-wide guarded mutex (member of generated base, not Fw/Comp); async kind: calls virtual <port>_preMsgHook(portNum,args) (default empty), serializes [msgType][portNum][args] into an internal buffer and m_queue.send with the FPP-declared priority and queue-full policy (assert=default: FW_ASSERT on non-OP_OK; block: BLOCKING send; drop: on FULL increment m_msgsDropped and return; hook: call overridable hook). ## Wire formats

### Active component EXIT message

Exactly one field: I32 value 0 (ACTIVE_COMPONENT_EXIT), big-endian (SerialBufferBase::serializeFrom default Endianness::BIG), in a buffer of capacity sizeof(ACTIVE_COMPONENT_EXIT)=sizeof(int)=4. Sent with priority 0, NONBLOCKING; send status discarded. Defined in ActiveComponentBase::exit() (/home/user/fprime/Fw/Comp/ActiveComponentBase.cpp lines 8-14, 49-54). No portNum field follows — generated doDispatch must check for the exit sentinel before reading portNum.

### Async port/command/internal-interface queue message (autocoded; inferred from fpp 3.3.0 contract + exit-message compatibility)

[msgType: FwEnumStoreType=I32 BE — generated per-component enum whose first entry (the exit sentinel) equals Fw::ActiveComponentBase::ACTIVE_COMPONENT_EXIT=0][portNum: FwIndexType=I16 BE (platform-configurable)][each port argument serialized in declaration order via its serializeTo/serializeFrom, big-endian; strings as FwSizeStoreType=U16 BE length + bytes; enums as their FwEnumStoreType-sized rep]. The whole message must fit the component's computed max msgSize passed to createQueue; Os::Queue::send rejects larger with SIZE_MISMATCH=4. Verify against fpp-to-cpp 3.3.0 output before freezing the Rust layout.

### Os::Queue message envelope

Raw byte array (U8*, FwSizeType size), size <= messageSize fixed at create(); priority FwQueuePriorityType=U8 carried out-of-band by the queue (max-heap: numerically higher priority dequeued first, FIFO within equal priority — /home/user/fprime/Os/Generic/Types/MaxHeap.cpp header comment). receive() requires destination capacity >= full messageSize and reports actual size received.

## Threading / concurrency

Passive: no queue/thread; all port handlers run on the caller's thread; guarded ports serialize entry through one component-wide mutex in the generated base. Queued: Os::Queue but no thread; async invocations enqueue from caller threads; user must drain from some sync/guarded handler via doDispatch() (NONBLOCKING receive, EMPTY -> MSG_DISPATCH_EMPTY) or dispatchAvailableMessages() (bounded by snapshot of available count). Active: Os::Task runs s_taskLoop (preemptive) or the per-call s_taskStateMachine (cooperative, m_task.isCooperative()); message loop = preamble once, then blocking doDispatch until MSG_DISPATCH_EXIT, then finalizer once, then DONE. Sync/guarded invocations on an active component still execute on the invoker's thread — only async messages run on the component thread. Os::Queue itself is thread-safe (delegate mutex + condition variables; BLOCKING send waits for space, BLOCKING receive waits for a message); global queue count and registry guarded by a static mutex. ObjBase::setObjRegistry and the port-trace globals are unsynchronized (init-time only). m_msgsDropped increment is unsynchronized (call-side races possible). Lifecycle m_stage is only touched from the task routine.

## Porting notes

1) Model the three component kinds as composable layers: a Passive core (name, idBase, instance), a Queued layer adding the queue + MsgDispatchStatus, an Active layer adding the task + Lifecycle state machine. In Rust, doDispatch is naturally a trait method (trait QueuedComponent { fn do_dispatch(&mut self) -> MsgDispatchStatus }); keep the exact 4-variant enum and the exact state machine (one stage per call) so cooperative scheduling ports directly. 2) Replace the C++ registration-pointer plumbing (addCallComp with a static thunk + void*-style component pointer) with typed closures or a generated enum-of-messages per component: an async input port becomes a serializer into a message struct + queue sender; doDispatch becomes a match over the generated message enum. Keep the on-wire serialized form byte-identical (msgType I32 BE, portNum I16 BE, args BE) because GenericHub-style serialized ports expose these buffers across address spaces. 3) Keep Os::Queue as a trait (QueueInterface) with the exact Status/BlockingType enums and the facade-level checks (ALREADY_CREATED, UNINITIALIZED, SIZE_MISMATCH before delegating); implement the default with a binary max-heap keyed by (priority DESC, FIFO order) plus Mutex/Condvar. 4) Port connection = handing the output port an input-port reference; in Rust use an enum Connection<T> { Typed(&InputPort<T>), Serial(&dyn SerialInput) } mirroring m_port vs m_serPort, with invoke asserting connected. isConnected must stay checkable pre-invocation. 5) Preserve assert-on-error philosophy: null checks, port range checks, and un-connected invocation are FW_ASSERT (panic/abort), not Result. 6) Make the config switches Cargo features (object-names, port-tracing, port-serialization, registration) and the platform type aliases central type defs; FwIndexType signedness (I16, -1 = unset port number) matters. 7) The exit path deserves a dedicated message-enum variant with value 0 injected ahead of all port messages, sent priority 0 NONBLOCKING. 8) Generated code contract (init order) must be reproduced by the Rust codegen or builder: construct -> init(queueDepth, instance) -> wire ports -> regCommands() -> loadParameters() -> start() -> ... -> exit() -> join() -> deinit().

## Gotchas

- exit() sends the EXIT message NONBLOCKING at priority 0 and ignores the send status: on a full queue the component never exits, and with a priority queue every pending higher-priority message is processed first.
- The EXIT message body is just the 4-byte I32 sentinel with NO portNum field; a doDispatch that unconditionally reads portNum after msgType will misparse it.
- MSG_DISPATCH_EXIT only terminates active components; QueuedComponentBase::dispatchAvailableMessages just returns it (break from its loop) — queued components have no lifecycle machine.
- dispatchAvailableMessages snapshots getMessagesAvailable() once; messages enqueued during the loop are NOT dispatched in that call (bounded-work guarantee for rate-group-driven queued components).
- ActiveComponentBase::dispatch() returns MSG_DISPATCH_EMPTY for cooperative tasks with an empty queue but the DISPATCHING stage treats anything != MSG_DISPATCH_EXIT as 'stay in stage' — EMPTY is not an error and not an exit.
- Os::Queue::receive requires destination capacity >= the queue's full messageSize (capacity < messageSize -> SIZE_MISMATCH), not >= the actual pending message's size.
- Queue priority ordering: numerically HIGHER FwQueuePriorityType dequeues first; ties are FIFO (MaxHeap doc comment). Priority 0 is the lowest.
- InputSerializePort::invokeSerial always returns FW_SERIALIZE_OK regardless of what the callback did, whereas typed input ports' invokeSerial returns the argument-deserialization status — a hub cannot detect malformed pass-through data at this layer.
- OutputPortBase::registerSerialPort sets m_connObj AND m_serPort; typed connection (addCallPort in generated code) sets m_connObj and the typed pointer — isConnected() is true in both cases, so 'connected' does not imply 'typed peer'.
- PortBase constructs ObjBase with nullptr name, so every port is literally named "NoName" until topology code calls setObjName; component ctor takes the real name.
- The guarded-port mutex, port arrays, and message buffers are all in the FPP-generated component base, not in Fw/Comp — Fw/Comp alone cannot run a component.
- PassiveComponentBase::init(instance) is protected and takes only instance; queue creation happens via the generated init calling createQueue, and the queue id passed to Os::Queue::create is getInstance(), not a unique id.
- sizeof(ACTIVE_COMPONENT_EXIT) is sizeof an unscoped enum constant (== sizeof(int) == 4): the exit buffer capacity is exactly 4 bytes; a Rust port using a larger discriminant changes the wire size.
- Queue name defaults to the component object name only when FW_OBJECT_NAMES==1, else "CompQ_<count>"; task name likewise "ActComp_<count>" — counts are global and mutex-guarded.
- SimpleObjRegistry::clear() leaves dangling pointers recoverable by a subsequent regObject; dtor unregisters the global registry, so registry lifetime must outlive object init() calls, and ObjBase::init() may be called multiple times (each call re-registers, duplicating entries).
- Fw::ObjectName truncates names silently to FW_OBJ_NAME_BUFFER_SIZE-1 (79) chars; toString truncation failure yields an empty string, not a truncated one.
- FwIndexType is signed I16 by default (m_portNum init -1); port-count loops and portNum asserts rely on signedness — using usize in Rust changes the 'unset' sentinel and assert behavior.
- Task default sentinels are type maxima (TASK_DEFAULT = FwSizeType::max, TASK_PRIORITY_DEFAULT = 255 for U8), not zero.
- Os::Queue and Os::Task use placement-new delegate storage with hard asserts that the delegate address equals the storage address; ALREADY_CREATED is detected via m_depth/m_size, so a failed create can be retried but a successful one cannot be re-created.
