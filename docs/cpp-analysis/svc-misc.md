# Svc utilities: TlmPacketizer, SystemResources, ComLogger, PassiveConsoleTextLogger (ConsoleTextLoggerImpl), ActiveTextLogger + LogFile, Svc/Types/EventSeverityFilter

> Analysis of the C++ F Prime implementation (github.com/nasa/fprime) produced to guide this Rust port.
> File paths refer to the C++ tree.

## Overview

Four remaining Svc utility components. TlmPacketizer (active) is an alternative to TlmChan: instead of per-channel packets it pre-lays-out fixed packets from a compile-time packet table, copies each incoming serialized channel value into pre-computed byte offsets of every packet containing it, and on each Run tick evaluates per-(section,group) rate/enable logic and emits whole FW_PACKET_PACKETIZED_TLM ComBuffers on an output port array. Sections are a configurable resampling dimension (default REALTIME/RECORDED); each packet has a numeric group/level 0..3; a static [section][group] -> port-index map picks the output port. SystemResources (passive, guarded) samples Os::Cpu / Os::Memory / Os::FileSystem::getFreeSpace("/") on each rate-group tick and writes 21 telemetry channels. ComLogger (active) writes Fw::ComBuffers to rotating `<prefix>_<timeBase>_<sec>_<usec06>.com` files with an optional U16 big-endian length prefix per record and a `.CRC32` big-endian sidecar written on close. The two text loggers share Svc::EventSeverityFilter (6 filterable severities + per-ID filter list of 25) and the identical `EVENT: (id) (base:sec,usec) SEV: text` format string; ActiveTextLogger additionally re-queues the formatted string through a drop-policy internal port onto its own thread and optionally appends to a size-capped, backup-suffixed log file. NOTE: this repo's TlmPacketizer is heavily modernized vs upstream (sections, rate logic, external params, RedBlackTreeMap channel index) — do not port from upstream F Prime.

## Wire formats

### Packetized telemetry packet (FW_PACKET_PACKETIZED_TLM) — TlmPacketizer PktSend ComBuffer

Big-endian, fixed length per packet, built once at setPacketList and mutated in place. Byte offsets: [0..2) FwPacketDescriptorType U16 = 0x0004 (ComCfg::Apid::FW_PACKET_PACKETIZED_TLM); [2..4) FwTlmPacketizeIdType U16 = the packet ID from the packet table; [4..15) Fw::Time SERIALIZED_SIZE=11 = timeBase U16 + timeContext U8 + seconds U32 + useconds U32 (rewritten on every send from the packet's latestTime); [15..packetLen) the concatenated raw serialized channel values, each at the fixed offset assigned in table order, each occupying exactly the table-declared channelSize bytes (NO ids, NO per-channel times, NO length prefixes, NO channel count). Total packetLen = 15 + sum(channelSize) and is FW_ASSERTed <= FW_COM_BUFFER_MAX_SIZE (512). Unwritten channel bytes are the zeros memset at configuration time (or stale bytes if a shorter value was later copied over a longer one). Ground decodes purely from the dictionary packet definition. ComBuffer length is fixed at packetLen for the life of the packet.

### TlmPacketizer packet-list configuration tables (C++ static data, not a wire format)

struct TlmPacketizerChannelEntry { FwChanIdType id; FwSizeType size; }; struct TlmPacketizerPacket { const TlmPacketizerChannelEntry* list; FwTlmPacketizeIdType id; FwChanIdType level; FwChanIdType numEntries; }; struct TlmPacketizerPacketList { const TlmPacketizerPacket* list[MAX_PACKETIZER_PACKETS=50]; FwChanIdType numEntries; }. constexpr Svc::TlmPacketizerPacket IGNORE_OMIT_LIST = {nullptr, 0, 0, 0} is the sentinel to disable ignore-list handling. `level` is the group (must be <= MAX_CONFIGURABLE_TLMPACKETIZER_GROUP=3). Supplied by the deployment, not FPP-generated in this repo.

### TlmPacketizer SectionConfigs / SectionEnabled (telemetry + external param serialization)

GroupConfig = enabled: Fw.Enabled U8 (DISABLED=0, ENABLED=1) | forceEnabled: Fw.Enabled U8 | rateLogic: RateLogic I32 (FPP default enum rep; SILENCED=0, EVERY_MAX=1, ON_CHANGE_MIN=2, ON_CHANGE_MIN_OR_EVERY_MAX=3) | min: U32 | max: U32 = 14 bytes big-endian. GroupConfigs = 4 x GroupConfig = 56 bytes. SectionConfigs = 2 x GroupConfigs = 112 bytes (channel id 0 / param SECTION_CONFIGS). SectionEnabled = 2 x Fw.Enabled U8 = 2 bytes (channel id 1 / param SECTION_ENABLED). TelemetrySection serializes as I32 (REALTIME=0, RECORDED=1, NUM_SECTIONS=2) in command args and in the SectionUnconfigurable event.

### TlmPacketizer command argument buffers (big-endian)

SET_LEVEL: U32 level (4B). SEND_PKT: U32 id + I32 section (8B). ENABLE_SECTION: I32 section + U8 enable (5B). ENABLE_GROUP / FORCE_GROUP: I32 section + U32 tlmGroup + U8 enable (9B). CONFIGURE_GROUP_RATES: I32 section + U32 tlmGroup + I32 rateLogic + U32 minDelta + U32 maxDelta (20B). SystemResources ENABLE: U8 enable (1B).

### ComLogger .com file record stream

Sequence of records with no file header and no trailer. storeBufferLength=true (default): each record = U16 BIG-ENDIAN length (the ComBuffer size masked with & 0xFFFF, asserted < 65536) followed by exactly that many raw ComBuffer bytes. storeBufferLength=false: raw ComBuffer bytes only, back to back. File name: `<prefix>_<timeBase:U16 decimal>_<seconds:U32 decimal>_<useconds:U32 zero-padded to 6>.com`. Rotation: a new file is started when (m_byteCount + size [+2]) > maxFileSize, evaluated before writing; m_byteCount counts only successfully written bytes.

### ComLogger .CRC32 sidecar (via Os::ValidateFile::createValidation)

File name = `<comFileName>.CRC32` (HASH_EXTENSION_STRING from Utils/Hash/Crc32/Crc32.hpp; HASH_DIGEST_LENGTH=4). Content = 4 bytes, the CRC-32 (IEEE 802.3, init 0xFFFFFFFF, final one's-complement) of the .com file, serialized through Fw::HashBuffer::serializeFrom(U32) i.e. BIG-ENDIAN. The file is hashed in VFILE_HASH_CHUNK_SIZE=256-byte chunks. IMPORTANT: this is NOT the same encoding as Utils::CRCChecker's `<name>.CRC32`, which memcpys the U32 in NATIVE endianness — docs/cpp-analysis/utils-misc.md conflates the two; ComLogger's sidecar goes through ValidateFile and is big-endian.

## Threading / concurrency

TlmPacketizer (ACTIVE, own Os::Task + queue): TlmRecv and TlmGet are SYNC — they execute on every producer's thread and are protected ONLY by the component's own Os::Mutex m_lock, which is taken and released once per packet inside the copy loop (not around the whole handler). The RedBlackTreeMap lookup, the ignored/oversize checks and the m_channels entry read are performed WITHOUT the lock; entry.hasValue is written inside the lock after the memcpy so TlmGet cannot observe a VALID-but-empty entry. Run, controlIn, configureSectionGroupRate, pingIn and all six commands are ASYNC (component thread, default assert-on-queue-full policy — no `drop`/`hook` declared). Run takes m_lock twice per packet: once to read/clear `updated` and read `level`, once to copy the whole BufferEntry; the rate-logic evaluation and m_packetFlags/m_groupConfigs/m_sectionEnabled mutation are unlocked but all live on the component thread — except that controlIn/ENABLE_SECTION also run on that same thread, so no cross-thread races there. setPacketList is an unlocked init-time API. SystemResources (PASSIVE): `run` is a GUARDED input and ENABLE is a GUARDED command, so both take the single component mutex; sampling happens on the rate-group caller's thread. ComLogger (ACTIVE): comIn, pingIn and CloseFile are all ASYNC, so all file I/O and all state (m_fileMode, m_byteCount, throttle flags) live on the component thread; no additional locking. The Os::Mutex/Utils::Hash includes in ComLogger.hpp are vestigial. PassiveTextLogger: fully synchronous on the emitting thread; filters and Fw::Logger::log run in the producer's context (Fw::Logger is the serializing point). ActiveTextLogger (ACTIVE): formatting + both filters run on the CALLER thread inside TextLogger_handler; the formatted 256-byte string is handed to the component thread through the internal port TextQueue whose queue-full policy is `drop` (silent, counted in the base-class m_msgsDropped); console printing and file writing happen on the component thread, which is exactly the ordering guarantee the component exists to provide.

## Rust feasibility (safe, zero-dependency std)

Everything here is implementable in safe, dependency-free std Rust; there is no ioctl/zlib/unsafe requirement. Specifics: (a) Os::Cpu on Linux reads /proc/stat with ordinary file I/O and integer parsing — a direct port; getCount uses sysconf(_SC_NPROCESSORS_ONLN), for which std offers `std::thread::available_parallelism()` (returns online/available parallelism, which can differ from _SC_NPROCESSORS_ONLN under cgroup/affinity restrictions) — a faithful alternative is to count `cpuN` lines in /proc/stat, which also keeps _getTicks' index validity check consistent; fall back to available_parallelism on non-Linux. (b) Os::Memory on Linux uses sysinfo(2), which std does not expose; the best zero-dependency substitute is parsing /proc/meminfo `MemTotal:`/`MemFree:` (both in kB — multiply by 1024 to reproduce the byte-valued Usage, then the component divides by 1024 again). Note this is MemFree, matching sysinfo's freeram (NOT MemAvailable) — do not "improve" it or the used figure changes. On non-Linux return Generic::Error so the component simply skips the two channels, exactly as the C++ error path does. (c) Free space uses statvfs(2), which std does not expose either; there is no safe std equivalent. Options, in order of fidelity: shell out to `df -k -P /` and parse (fragile, adds a process spawn to a flight-path rate-group tick — not recommended), read /proc/self/mountinfo + the filesystem's own statistics (not available without syscalls), or feature-gate a `libc`-backed implementation behind a non-default cargo feature while the default build returns FileSystem::Status::NotSupported and skips NON_VOLATILE_TOTAL/FREE. Given the zero-dependency constraint, recommend: define the `FileSystem::get_free_space` seam now, implement it as NotSupported by default with a documented divergence note, and let a project supply a real implementation through the OSAL seam (this matches how the C++ code already returns NOT_SUPPORTED on VxWorks). (d) The C++ float math (F32 divide, isnan check, 100.0f default on zero delta) maps 1:1 to f32 in Rust; keep `is_nan()` and the same 100.0 fallbacks. (e) Integer division by 1024 must stay integer (u64), not float. (f) ComLogger's `%06u` useconds formatting maps to `format!("{:06}", usec)`; the `%u` for FwTimeBaseStoreType is plain decimal on a u16.

## Gotchas

- TlmPacketizer::setPacketList's `startLevel` parameter is accepted and NEVER USED — no initial level is applied. All groups start ENABLED from TELEMETRY_SECTION_DEFAULTS; only SET_LEVEL changes them.
- PktSendCounters::prevSentCounter is initialized to U32::MAX (not 0), and the increment is skipped at U32::MAX. Combined with updateFlag==NEVER_UPDATED gating, the first data arrival satisfies both min and max immediately and sends at once.
- The counter increment happens AFTER the enabled/silenced/never-updated gate, so a disabled or SILENCED group's counter FREEZES (documented behavior); it resumes on re-enable and can trip MIN immediately.
- SEND_PKT emits PacketSent(id) at command time, before the packet is actually emitted by the next Run tick; it marks REQUESTED only for the one requested section and also sets updated=true + latestTime=now on the shared fill buffer, which makes OTHER sections see the packet as newly updated too.
- REQUESTED bypasses port-connection? No — the isConnected_PktSend_OutputPort check comes FIRST and skips the section even for REQUESTED, and the REQUESTED flag is then never cleared for that section (it stays set until a send happens), permanently bypassing enable/rate checks for that packet+section.
- TlmRecv takes/releases m_lock once per matching packet, so a channel present in several packets can interleave with a concurrent Run; each packet gets latestTime from the last writer to touch it.
- TlmGet returns the channel bytes padded to the table's MAX channelSize — the tail may contain junk from a previously longer value or the configuration-time zeros. The caller must know the real width from the dictionary.
- An oversized TlmRecv value (val.getSize() > entry.channelSize) is REJECTED with WARNING_HI OversizedChannel (throttle 10), not asserted — this is the hub/cross-address-space guard.
- setPacketList FW_ASSERTs (crashes) if the same channel id appears in two packets with DIFFERENT sizes, and also if a channel appears in both a packet and the ignore list (packets are processed first, so entry.ignored is false when the ignore loop re-finds it).
- missingChannel's 25-slot table never resets and never evicts: after 25 distinct unknown channel ids, NoChan events stop entirely for the life of the process.
- controlIn (the port) sets m_sectionEnabled WITHOUT writing the SectionEnabled telemetry channel, whereas the ENABLE_SECTION command does write it — the channel can go stale.
- The packet time bytes live at offset 4 (after descriptor U16 + packet id U16), not immediately after the descriptor; setPacketList's initial packetLen accounts for the time but only the descriptor and id are serialized there, leaving bytes 4..15 zero until the first send.
- The same packet is sent once per flagged section, and if TELEMETRY_SEND_PORT_MAPPING maps two section/group pairs to the same port index, the identical buffer is delivered to that port twice in one tick.
- TlmPacketizer's Run/controlIn/command ports have NO drop or hook policy — queue overflow ASSERTS.
- ComLogger has exactly one command, CloseFile (opcode 0x00). There is no SEND_FILE/SendFile; file retrieval is another component's job.
- ComLogger's .CRC32 sidecar is written via Os::ValidateFile and is BIG-ENDIAN (HashBuffer::serializeFrom); Utils::CRCChecker's identically-named sidecar is native-endian raw memcpy. docs/cpp-analysis/utils-misc.md states the native-endian form for ComLogger — that is wrong; follow ValidateFileCommon.cpp.
- ComLogger rotation uses strict `>` against maxFileSize including the 2-byte length prefix in the projection, and it never rotates or closes on a WRITE failure — it just throttles the event and keeps going with a possibly-truncated record already partially written.
- If the length prefix write fails, writeComBufferToFile returns early and the payload is never written, silently desynchronizing nothing (the file simply has no record) — but m_byteCount is not advanced either.
- ComLogger's destructor closes the file and writes the hash but deliberately emits NO FileClosed event (virtual-call-during-destruction hazard).
- ComLogger constructed with only a name has m_initialized=false; every comIn then emits the throttled (5) FileNotInitialized event and the buffer is DROPPED.
- SystemResources hardcodes the path "/" for free-space telemetry and writes NON_VOLATILE_FREE before NON_VOLATILE_TOTAL.
- compCpuUtil returns 100.0% when the total tick delta is zero (fast sampling), and Cpu() silently SKIPS a sample (no telemetry for that core that cycle) when either counter went backwards.
- Memory and disk figures are integer-divided by 1024 (bytes -> KiB) after being computed in bytes; do not carry fractional values.
- Per-CPU telemetry is written with an explicitly constructed zero Fw::Time so the generated base fills in the current time from the Time port; the average CPU channel uses the default-argument path. Behaviorally identical, but do not hardcode a zero timestamp.
- SystemResources' ENABLE command always returns CmdResponse::OK and performs no validation of the enum.
- ActiveTextLogger's LogFile does NOT rotate: once the max size would be exceeded, the file is closed and m_openFile is set false permanently — all subsequent file logging is silently dropped (console logging continues).
- LogFile's backup search treats 'getFileSize failed' as 'name is free', so a permissions error on an existing file makes it pick that name and truncate it.
- Both text loggers filter DIAGNOSTIC by default (config default = false = dropped) and never filter FATAL (EventSeverityFilter::toIndex returns FAILURE for FATAL, and isFiltered maps that to 'not filtered').
- ActiveTextLogger formats on the caller thread but prints on its own thread via a `drop`-policy internal port — under queue pressure text messages are silently lost and only visible as the base class's m_msgsDropped counter.
