# Svc core services: CmdDispatcher, EventManager, TlmChan, ActiveRateGroup, PassiveRateGroup, RateGroupDriver, Health, FatalHandler/Fatal, Ping/Sched/Cycle ports, PolyDb

> Analysis of the C++ F Prime implementation (github.com/nasa/fprime) produced to guide this Rust port.
> Source tree analyzed: local clone at commit of 2026-08. File paths refer to that C++ tree.

## Overview

These Svc components form the C&DH backbone of an F Prime deployment. CommandDispatcher receives serialized command packets (Fw.Com) from sequencers/uplink, decodes opcode, looks it up in a registration table populated at init via CmdReg ports, forwards the arg buffer to the owning component, tracks in-flight commands by sequence number, and forwards completion status back to the originating caller port. EventManager receives events on a sync Fw.Log port, applies severity and per-ID filters, re-queues surviving events through an internal async port to its own thread, serializes them as FW_PACKET_LOG com packets to PktSend, and announces FATALs on FatalAnnounce (Svc.FatalEvent) which FatalHandler consumes (Linux: sleep 1s, SIGABRT, exit(1); baremetal: infinite loop; VxWorks: taskSuspend(0)). TlmChan stores latest channel values in a double-buffered seeded hash table (guarded TlmRecv/TlmGet ports) and, on each async Run call, swaps buffers and serializes updated entries into FW_PACKET_TELEM com packets. Rate scheduling: RateGroupDriver (passive, ISR-safe) divides a primary tick (Svc.Cycle carrying Os::RawTime) across CycleOut ports via a divisor/offset table with product-of-divisors rollover; ActiveRateGroup (async CycleIn with drop) and PassiveRateGroup (sync) fan the tick out to member Sched ports with per-port context values and record cycle-time telemetry/slips. Health (queued component) pings components (Svc.Ping key exchange) from its sync Run handler, counting cycles until warn (WARNING_HI event) and fatal (FATAL event) thresholds, strokes a watchdog, and supports enable/threshold commands. PolyDb is a passive guarded key-value store of Fw::PolyType measurements indexed by a config enum. NOTE: this repo is a modernized fork — EventManager was formerly ActiveLogger; TlmChan hashing is seeded; CmdDispatcher uses RedBlackTreeMap/ArrayMap instead of linear arrays.

## Wire formats

### Command packet (Fw::CmdPacket; uplink, consumed by CmdDispatcher)

Big-endian: [FwPacketDescriptorType descriptor = U16 0x0000 (FW_PACKET_COMMAND)] [FwOpcodeType opcode = U32] [raw serialized args, no length prefix, to end of ComBuffer]. Defined by Fw/Cmd/CmdPacket.cpp deserializeFrom (serializeTo asserts false — FSW never serializes commands). Empty remainder => empty arg buffer (explicit resetSer). Type mismatch => FW_DESERIALIZE_TYPE_MISMATCH.

### Fw::Time serialized (TimeValue struct)

Big-endian 11 bytes: [timeBase = FwTimeBaseStoreType U16] [timeContext = FwTimeContextStoreType U8] [seconds = U32] [useconds = U32]. Fw/Time/Time.fpp struct TimeValue; SERIALIZED_SIZE in Fw/Time/Time.hpp. deserializeFrom rejects useconds >= 1000000 (FW_DESERIALIZE_INVALID_DATA).

### Event/log packet (Fw::LogPacket; EventManager PktSend output)

Big-endian: [descriptor = U16 0x0002 (FW_PACKET_LOG)] [event id = FwEventIdType U32] [Fw::Time 11 bytes] [event argument bytes serialized raw with OMIT_LENGTH — no length field; length implied by com buffer size]. Fw/Log/LogPacket.cpp serializeTo. Max total = 512-byte ComBuffer.

### Telemetry packet (Fw::TlmPacket; TlmChan PktSend output)

Big-endian, built incrementally in a 512-byte ComBuffer: [descriptor = U16 0x0001 (FW_PACKET_TELEM)] then N repetitions of [channel id = FwChanIdType U32] [Fw::Time 11 bytes] [channel value bytes, OMIT_LENGTH, length = stored TlmBuffer size]. Fw/Tlm/TlmPacket.cpp addValue/resetPktSer. Entry count (m_numEntries) is NOT in the packet body; addValue precomputes room as sizeof(FwChanIdType)+Time::SERIALIZED_SIZE+buffer.getSize(). TlmPacket::serializeTo/deserializeFrom (used elsewhere, e.g. TlmPacketizer path) prepend a FwSizeType entry count — not used on TlmChan's downlink path, which sends pkt.getBuffer() directly.

### Command status forwarding (seqCmdStatus port call, in-memory contract)

Port args (opCode: U32, cmdSeq: U32, response: CmdResponse U8) but CommandDispatcherImpl.cpp line 66 passes the tracked CONTEXT value (the U32 given with the original seqCmdBuff call) in the cmdSeq position, not the dispatcher's internal sequence number.

## Threading / concurrency

Active components (CommandDispatcher, EventManager, TlmChan, ActiveRateGroup) each own an Os::Task + Os::Queue; async input ports and async commands serialize their args into queue messages executed on the component thread; sync/guarded ports run on the caller thread (guarded takes the single component mutex). FPP queue-full policies used here: `drop` (ActiveRateGroup.CycleIn, EventManager.run, EventManager internal loqQueue — silently drop + increment m_msgsDropped), `hook` (CmdDispatcher.seqCmdBuff — calls seqCmdBuff_overflowHook), default (assert). ActiveRateGroup's slip detection depends on CycleIn_preMsgHook running on the SENDER (driver/ISR) thread before enqueue, setting m_cycleStarted while the handler may still be mid-cycle. EventManager.LogRecv is sync: severity/ID filtering runs on every producer's thread; m_filteredIDs guarded by a dedicated Os::Mutex because command mutations happen on the EventManager thread; serialization/emission happens on EventManager's thread via internal port. TlmChan: TlmRecv/TlmGet guarded by the component mutex; Run_handler (component thread) takes the same mutex only to swap the double buffer and clear/individually-reset updated flags, so producers write into the new active store while Run drains the inactive one. Health is a queued component (queue, no thread): its sync Run handler (rate group thread) drains up to queue_depth queued messages (async PingReturn + async commands) via doDispatch() before the ping sweep — so all Health logic executes on the rate group thread. PassiveRateGroup and RateGroupDriver are passive and may run in ISR context; PassiveRateGroup uses relaxed std::atomic<U32> CAS loops for m_maxTime and per-port HWMs; RateGroupDriver has no locking at all (single-caller assumption). PolyDb ports guarded by the component mutex.

## Porting notes

1) Model each FPP port kind as a trait; codegen contracts (ComponentBase classes) become generated or macro-derived structs holding output-port connections, an MPSC queue for active/queued components, and helper methods (log_*, tlmWrite_*, cmdResponse_out, isConnected_*). Reproduce the three queue-overflow policies (assert/drop+counter/hook) per port. 2) Keep exact numeric config as consts in a config crate mirroring default/config: CMD_DISPATCHER_DISPATCH_TABLE_SIZE=150, CMD_DISPATCHER_SEQUENCER_TABLE_SIZE=25, TELEM_ID_FILTER_SIZE=25, filter defaults (DIAGNOSTIC off), TLMCHAN {15,99,500,cap}, ACTIVE_RATE_GROUP_OVERRUN_THROTTLE=5, port counts (30/5/10/10/3/25). 3) CmdDispatcher: BTreeMap<u32,i16> capped at 150 for the dispatch table (insertion-order 'slot' in the OpCodeRegistered event = size before insert) and a fixed-capacity array map keyed by u32 seq for tracking; ## Gotchas

- This repo is a modernized fork of upstream F Prime: ActiveLogger→EventManager (with FATAL always-on filter and no event buffers/log file), TlmChan hash is seeded+Murmur3/Wang (upstream: (id%MOD)%SLOTS), CmdDispatcher uses RedBlackTreeMap/ArrayMap, FwPacketDescriptorType is U16 (upstream legacy U32). Port a diff-checked upstream at your peril — follow THIS code.
- EventManager_Enabled {ENABLED=0, DISABLED=1} is the reverse of Fw::Enabled {DISABLED=0, ENABLED=1}; confusing them silently inverts filter commands.
- CommandDispatcher.seqCmdStatus_out sends the caller-supplied context in the cmdSeq argument position — sequencers rely on getting their context back, not the dispatcher's sequence number.
- CommandDispatcher m_seq increments after every seqCmdBuff message (including invalid-opcode failures) but NOT on malformed-packet early return; tracked commands are keyed by the pre-increment value.
- A command whose target compCmdSend port is unconnected is reported as InvalidCommand/INVALID_OPCODE even if the opcode is registered (the connectivity check is ANDed with the table lookup).
- Health thresholds fire on exact equality (cycleCount == fatalCycles), fatal checked BEFORE warn (warn==fatal is legal and produces only FATAL); counters keep incrementing past fatal so the FATAL event fires exactly once per hang.
- Health wrong-key ping response does NOT reset cycleCount — the entry will still march to HLTH_PING_LATE.
- Health is a queued (thread-less) component: async handlers only ever run inside Run_handler's manual doDispatch loop, bounded to queue_depth dispatches per rate-group cycle.
- ActiveRateGroup slip detection: m_cycleStarted is set in CycleIn_preMsgHook on the SENDER thread and cleared at handler start — a Rust port must preserve this cross-thread flag (relaxed atomic bool) or slips are never detected. Overrun event uses a manual count-up/count-down throttle (5), separate from FPP event throttling.
- TlmChan TlmGet reads BOTH buffers and picks the newer timestamp; with INCOMPARABLE time bases it prefers the inactive entry only if its updated flag is set. TlmGet can return VALID data whose updated flag was already cleared by downlink.
- TlmChan Run clears the NEW active buffer's updated flags right after the swap — entries deferred by the per-run cap in the previous cycle are dropped, not requeued.
- TlmChan hash seed differs every boot, so bucket assignment/downlink ordering is non-deterministic run-to-run; entries are emitted in bucket-allocation order of the inactive store, not ID order.
- RateGroupDriver m_ticks starts at 0, so every offset-0 rate group fires on the very first tick; configure() resets rollover to 1 (reconfigure-safe) and asserts offset==0||offset<divisor.
- LogPacket/TlmPacket serialize argument bytes with OMIT_LENGTH — lengths are implicit from packet size (events) or from ground dictionaries (telemetry values); do not emit length prefixes.
- TlmPacket::addValue reserves room using sizeof(FwChanIdType)+Time::SERIALIZED_SIZE+valueSize, and TlmChan asserts if a single channel cannot fit an empty packet.
- EventManager internal queue and run port use FPP `drop`; dropped-event count comes from the component-base m_msgsDropped counter surfaced as EventsDropped telemetry; TlmChan's Run port has NO drop and asserts on queue overflow.
- PolyDbCfg.PolyDbEntry enum skips POLYDB_ENTRY_02, so names and auto-assigned values diverge (POLYDB_ENTRY_03=2 ... POLYDB_ENTRY_09=8); DB size is NUM_CONSTANTS=9.
- FwIndexType is signed I16 (Health::findEntry returns -1); FwSizeType is U64; asserts static_assert on these properties — keep signedness in the Rust type choices.
- Fw::Time::compare ignores timeContext but returns INCOMPARABLE across different TimeBase values; TlmChan and others branch on this.
- SET_EVENT_FILTER is a sync command (executes on the dispatcher thread), while SET_ID_FILTER/DUMP_FILTER_STATE are async — the ID-filter mutex exists precisely because of this split plus the sync LogRecv reader.
