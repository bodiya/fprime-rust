# Fw core types and serialization (Fw/Types, Fw/Buffer, Fw/Com, config defaults)

> Analysis of the C++ F Prime implementation (github.com/nasa/fprime) produced to guide this Rust port.
> Source tree analyzed: local clone at commit of 2026-08. File paths refer to that C++ tree.

## Overview

This subsystem defines F Prime's primitive type aliases, the configurable "Fw*" type layer, the byte-exact serialization engine, string classes, assert machinery, and the two buffer abstractions (LinearBufferBase-family owning/wrapping serialization buffers and Fw::Buffer, a non-owning data descriptor). Everything else in F Prime (ports, commands, telemetry, events, parameters, framing) is built on the wire encoding implemented in Fw/Types/Serializable.cpp: big-endian-by-default primitives, a 1-byte 0xFF/0x00 bool, a U16 (FwSizeStoreType) length prefix for variable-length buffers/strings, and enum storage via representation type (FPP) or FwEnumStoreType=I32 (C++ enums). The type layer is 3 stages: BasicTypes.h (I8..U64, F32/F64 from stdint), Platform/PlatformTypes (per-platform: pointer-cast int, Platform{Size,SignedSize,Index,AssertArg,...}Type — the unix platform pins U64/I64/I16/I32), and FPP alias files (default/config/FpConfig.fpp) mapping Fw* names onto platform types plus GDS-visible dictionary types (FwSizeStoreType=U16, FwPacketDescriptorType=U16, FwIdType=U32...). FpConfig.h holds boolean feature switches; FpConstants.fpp holds buffer-size constants (FW_COM_BUFFER_MAX_SIZE=512 etc.). This report pins exact byte layouts, enum values, status codes, and lifecycle rules a Rust port must reproduce bit-for-bit.

### SerialBufferBase / LinearBufferBase — the serialization engine

Files: `Fw/Types/Serializable.hpp`, `Fw/Types/Serializable.cpp`

SerialBufferBase is the pure-virtual API; LinearBufferBase implements it over a flat byte array with 4 fields: m_buffAddr (U8*), m_capacity, m_serLoc (write offset == current size), m_deserLoc (read offset), all Serializable::SizeType=FwSizeType. Constructor asserts (buffAddr==nullptr)==(capacity==0). Write path: room check is `m_serLoc + sizeof(val) - 1 >= m_capacity` -> FW_SERIALIZE_NO_ROOM_LEFT; on every successful write m_serLoc += n and **m_deserLoc is reset to 0**. Read path: if m_serLoc == m_deserLoc -> FW_DESERIALIZE_BUFFER_EMPTY; else if (m_serLoc - m_deserLoc) < n -> FW_DESERIALIZE_SIZE_MISMATCH; else read and m_deserLoc += n. resetSer() zeroes both locs; resetDeser() zeroes m_deserLoc only; moveSerToOffset(o)=resetSer+serializeSkip(o) (skip leaves bytes unwritten); moveDeserToOffset(o)=resetDeser+deserializeSkip(o); deserializeSkip has the same empty/mismatch checks (so skip on fully-consumed buffer returns BUFFER_EMPTY). getSize()==m_serLoc; getDeserializeSizeLeft()==serLoc-deserLoc (asserts serLoc>=deserLoc); getSerializeSizeLeft()==capacity-serLoc. setBuff(src,len): capacity check then memcpy, serLoc=len, deserLoc=0; setBuffLen(len): serLoc=len, deserLoc=0, no copy. copyRaw(dest,size): requires dest.getCapacity()>=size (NO_ROOM_LEFT) and source remaining>=size (SIZE_MISMATCH); dest.setBuff(replaces dest content) then advance source deserLoc. copyRawOffset(dest,size): requires dest.capacity >= dest.size+size; appends via dest.serializeFrom(ptr,size,OMIT_LENGTH). operator=/copyFrom copies serLoc/deserLoc and memcpy of serLoc bytes (asserts both addrs non-null and src.serLoc<=dest capacity). serializeSize(FwSizeType,mode): range-checks against numeric_limits<FwSizeStoreType> -> FW_SERIALIZE_FORMAT_ERROR, else writes as FwSizeStoreType; deserializeSize reads FwSizeStoreType and widens. Deprecated serialize()/deserialize() overloads forward to the new names (bool noLength variant maps true->OMIT_LENGTH). STATIC_SERIALIZED_SIZE(maxSize)=sizeof(FwSizeStoreType)+maxSize.

## Wire formats

### Primitive integers (U16/I16/U32/I32/U64/I64)

Big-endian by default (MSB first), byte-by-byte shift stores; Endianness::LITTLE reverses order per-call. Signed values are static_cast to same-width unsigned and share the encoding (two's complement bytes). Defined in LinearBufferBase::serializeFrom/deserializeTo, /home/user/fprime/Fw/Types/Serializable.cpp lines 88-196 and 350-484. U8/I8: single byte; mode ignored.

### F32 / F64

memcpy bit-cast to U32/U64 respectively, then integer endianness rules (IEEE-754 asserted at compile time in BasicTypes.hpp). Serializable.cpp lines 198-210, 486-543.

### bool

1 byte: 0xFF = true (FW_SERIALIZE_TRUE_VALUE), 0x00 = false (FW_SERIALIZE_FALSE_VALUE) — FPP dictionary constants in default/config/FpConstants.fpp. Deserialization of any other byte value returns FW_DESERIALIZE_FORMAT_ERROR (Serializable.cpp lines 212-228, 499-521).

### Pointers (void*, serialized Fw::Buffer data field)

reinterpret_cast to PlatformPointerCastType (uint of pointer width; u64 on unix 64-bit) then integer encoding — wire width is platform-dependent. Serializable.cpp lines 230-236, 523-531.

### Length-prefixed byte buffer (INCLUDE_LENGTH) — also all strings

[FwSizeStoreType length (U16, default big-endian)] [length raw bytes]. serializeFrom(buff,len,INCLUDE_LENGTH) casts len to FwSizeStoreType with NO range check (silent truncation of the prefix if len>65535). Deserialize reads prefix, errors FW_DESERIALIZE_SIZE_MISMATCH if storedLength > remaining bytes or > caller max, then memcpys. OMIT_LENGTH: raw bytes only, count supplied/known out-of-band. Strings serialize as length-prefixed bytes of length() with NO null terminator on the wire (ConstStringBase::serializeTo -> serializeFrom(bytes,length)); string deserialize enforces prefix <= maxLength (capacity-1) and null-terminates in memory only. Serializable.cpp lines 244-273, 554-596; ConstStringBase.cpp lines 81-95; StringBase.cpp lines 113-137.

### LinearBufferBase serialized into another buffer

[FwSizeStoreType size (U16 BE)] [size bytes of content (bytes 0..serLoc of source)]. Pre-checks serLoc room for size+2. Deserialize into a LinearBufferBase reads prefix, checks against dest capacity and source remaining, memcpys, dest.setBuffLen(storedLength). Serializable.cpp lines 280-303, 602-634. STATIC_SERIALIZED_SIZE(maxSize)=2+maxSize; ComBuffer SERIALIZED_SIZE=514.

### serializeSize / deserializeSize

FwSizeType value stored on the wire as FwSizeStoreType (U16 BE). serializeSize range-checks and returns FW_SERIALIZE_FORMAT_ERROR if value outside U16 range (unlike the buffer-length path). Serializable.cpp lines 305-314, 636-643.

### Fw::Buffer (member serialization — NOT the wrapped data)

Field order in Buffer::serializeTo (Buffer.cpp lines 176-231): [data pointer as PlatformPointerCastType: 8B on 64-bit] [m_size: FwSizeType 8B] [m_context: U32 4B] [m_offset: FwSizeType 8B] [m_capacity: FwSizeType 8B] = 36 bytes on default 64-bit config, all BE by default. NOTE: order is pointer,size,context,offset,capacity — context BEFORE offset/capacity, differing from member declaration order. SERIALIZED_SIZE enum = 3*sizeof(FwSizeType)+sizeof(U32)+sizeof(U8*). Wrapped data bytes are never included; deserializeFrom reconstitutes the pointer via reinterpret_cast (only meaningful in-process/same address space) and rebinds m_serialize_repr to data+offset.

### Enums (framework convention)

FPP-defined enums serialize as their declared representation type (e.g. `enum X : U8` -> 1 byte; TimeBase : U16 -> 2 bytes BE). Raw C++ enums serialize via cast to FwEnumStoreType = I32 (4 bytes BE) — comment in default/config/FpConfig.fpp lines 82-84 and PolyType usage.

## Threading / concurrency

This layer is entirely passive and thread-unaware: no locks, no atomics. LinearBufferBase/Fw::Buffer instances are mutable value objects intended to be confined to one thread at a time (F Prime moves them between components by copy through message queues or by ownership handoff of Fw::Buffer descriptors). Two pieces of static mutable state exist and are NOT synchronized: (1) Fw::AssertHook::s_assertHook — a global singleton pointer with a push/pop chain via registerHook()/deregisterHook(), expected to be installed at init before tasks start; (2) nothing else in this subsystem. Assert functions may be called from any task and format into stack-local buffers, so they are reentrant apart from the hook pointer read. A Rust port can model buffers as plain &mut structs; the assert hook needs a Once/atomic-pointer or explicitly-unsafe global matching the install-before-threads contract.

## Porting notes

1) Make the wire codec a standalone module: a `SerializeStatus` enum with the exact 10 discriminants (values 0..9 matter for cross-boundary status reporting and the FPP shadow enums), an `Endianness` parameter defaulting to BIG on every call, and a `LinearBuffer` struct {storage, capacity, ser_loc, deser_loc} reproducing the exact state rules — especially `deser_loc = 0` on every successful write, and the BUFFER_EMPTY-vs-SIZE_MISMATCH distinction. Implement primitives with to_be_bytes/to_le_bytes; bool as 0xFF/0x00 with strict decode. 2) Make the configurable types Rust type aliases in one `fw_types` crate mirroring the FPP alias chain (FwSizeType=u64, FwSignedSizeType=i64, FwIndexType=i16, FwAssertArgType=i32, FwSizeStoreType=u16, FwEnumStoreType=i32, FwPacketDescriptorType=u16, FwIdType/FwOpcodeType/FwChanIdType/FwEventIdType/FwPrmIdType=u32, FwTimeBaseStoreType=u16, FwTimeContextStoreType=u8), with the invariants (unsigned/signed, width relations) as const assertions; keep them overridable via features/cfg like the C #ifndef scheme. 3) Split the C++ SerialBufferBase inheritance into two traits: `Serialize`/`Deserialize` for value types, and a buffer trait for the reader/writer; the C++ deprecated serialize()/deserialize() overloads need not be ported. 4) Fw::Buffer should become a descriptor struct with {original_ptr, offset, size, capacity, context} and the same bounds-asserting advance/set_data/set_size; its member-serialization (pointer + metadata) is only used for in-process port serialization — port it exactly (field order pointer,size,context,offset,capacity) but consider gating it, since deserializing a pointer is inherently unsafe in Rust and only valid same-address-space. getSerializer/getDeserializer map naturally to borrowing a writer/reader over data[offset..offset+size]. 5) Strings: model as fixed-capacity byte arrays with truncating From/assign, length = bounded scan, and length-prefixed (u16) serialization without NUL; keep STATIC_SERIALIZED_SIZE = maxLen+2 formulas since autocoded types size buffers with them. 6) Asserts: replace FW_ASSERT with a macro that evaluates the condition, captures up to 6 i32 args + file + line, and dispatches to a swappable hook (report/print/do) with the default writing `Assert: \"file:line\" args` (<=256 bytes) to stderr then panicking; keep the numArgs-explicit call shape so hook implementations (e.g. AssertFatalAdapter) port cleanly. 7) PolyType maps to a Rust enum, but serialize the tag as i32 with the exact discriminants and keep the compile-time-width-dependent numbering in mind (fix them to the all-widths-on values 0..12 unless targeting reduced configs). 8) Keep constants (FW_COM_BUFFER_MAX_SIZE=512, derived 506 arg-buffer sizes, string maxes, TRUE=0xFF) in a config module generated from or checked against FpConstants.fpp values, since GDS dictionaries embed them.

## Gotchas

- Every successful serializeFrom on a LinearBufferBase resets m_deserLoc to 0 — interleaved read/write loses read progress by design; a port that keeps the read cursor will desync framing code.
- The variable-length prefix is FwSizeStoreType=U16 even though sizes are u64: serializeFrom(buff,len,INCLUDE_LENGTH) silently truncates len via static_cast when writing the prefix (no range check), while serializeSize() DOES range-check and returns FW_SERIALIZE_FORMAT_ERROR — two different behaviors for the same wire field.
- Empty-vs-short distinction: deserialize returns FW_DESERIALIZE_BUFFER_EMPTY only when deser_loc == ser_loc exactly; any partial remainder yields FW_DESERIALIZE_SIZE_MISMATCH; deserializeSkip(0) on a fully-consumed buffer returns BUFFER_EMPTY, not OK.
- Fw::Buffer::serializeTo field order is pointer, size, context, offset, capacity — context comes before offset/capacity, not matching member declaration order; it serializes the pointer VALUE, never the wrapped bytes, and SERIALIZED_SIZE is pointer-width-dependent (36 bytes only on 64-bit).
- bool decode is strict: only 0xFF and 0x00 are accepted; anything else is FW_DESERIALIZE_FORMAT_ERROR (encode true is 0xFF, not 1).
- FwIndexType is SIGNED (i16 by default) — port indices/loop counters go negative-capable; FwSizeType is unsigned u64. Mixing them up breaks many FW_ASSERT bounds patterns.
- String serialization writes no NUL terminator on the wire and lengths are byte counts capped at capacity-1; StringBase::deserializeFrom writes into the target buffer even on failure (then NUL-terminates at maxLength), so 'leave unmodified on error' is only approximately true.
- PolyType's tag enum values shift when FW_HAS_16/32/64_BIT are disabled (members are preprocessor-conditional), and deserializeFrom overwrites m_dataType with an unvalidated tag before rejecting unknown values.
- FPP enums serialize by their declared representation type (U8/U16/...), but bare C++ enums use FwEnumStoreType=I32 — two different enum widths coexist on the wire.
- ExternalSerializeBufferWithMemberCopy copies the buffer POINTER (aliasing), ExternalSerializeBufferWithDataCopy copies bytes, plain ExternalSerializeBuffer forbids copying; Fw::Buffer::getSerializer/getDeserializer return the aliasing flavor by value — Rust ports must express this as borrows, not clones.
- LinearBufferBase capacity check uses `serLoc + sizeof(val) - 1 >= capacity`, and copyRaw checks dest total capacity (it REPLACES dest content via setBuff) while copyRawOffset checks capacity - current size (it APPENDS with OMIT_LENGTH).
- FILE_NAME_ARG changes type with assert level (const char* vs U32 for FW_FILEID_ASSERT) and SwAssert's line number is the LAST parameter after the variable args; unused args are transmitted as 0 alongside an explicit numArgs.
- FwPacketDescriptorType (U16) is defined in default/config/ComCfg.fpp, not FpConfig.fpp; derived buffer constants (FW_CMD_ARG_BUFFER_MAX_SIZE=506 etc.) depend on sizeof(FwOpcodeType)=4 and sizeof(FwPacketDescriptorType)=2 and change if those types are reconfigured.
- LinearBufferBase::operator= copies only serLoc bytes plus both cursor positions and asserts both buffers non-null — it is a content copy, not a rebinding; asserts (not errors) fire if dest capacity < src serLoc.
